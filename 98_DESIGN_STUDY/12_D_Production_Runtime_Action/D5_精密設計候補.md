## 1. Purpose

市場理解OSは、Production / Runtime Contextで複数Operational Actionが同時・連続・反復的に行われる場合のIndividual Authority Exercise、Applicable Authorization、MaterialなMulti-Action Relationship、Shared Constraint、Aggregate Effectを区別する。

個別ActionへのAuthorization Coverage、Condition Satisfaction、Proper Authority Exercise、Observed Successによって、集合全体のFormal Authorization、Aggregate Constraint Satisfaction、Aggregate Safety、Complete Execution、Proper Authority Exerciseを無条件に成立させない。

一方、複数Actionの存在だけで新しいAggregate Approval、Human Approval、Mandatory Central Controllerを普遍的に要求しない。

D5は新しいAuthority Grant、Risk Capacity、Execution Permission、Runtime Block、Conflict Precedence、Concurrency Protocolを独自に生成しない。

## 2. Individual Action / Multi-Action Boundary

Individual ActionはD1のSemantic IdentityおよびD2のRequest / Authorization / Authority Exercise / Execution Boundaryを継承する。

Batch、Sequence、Workflow、Strategy、Automated Processに属していても個別のMaterial Identity、Applicable Authorization、Authority Exercise、Execution Attempt、External Effectを無言で消去しない。

処理の集合化だけでFormal Authorityを成立させないが、Applicable Governanceに基づく正式なMulti-Action Operationは排除しない。

## 3. Material Multi-Action Relationship

Materialな時間関係、Dependency、Shared Constraint、Interference、Aggregate Effect、Shared Decision Originを区別する。

同一Actor、Strategy、Batch、Market、Process、Accountへの所属だけでMaterial Relationshipを決めず、異なる所属だけで非関係・Risk独立を推定しない。

Materialな関係が不明な場合、不明さを独立性の証拠として使わない。同一System内の全Actionを一つの無制限Aggregate Responsibilityに統合しない。

## 4. Action Set / Batch / Sequence

Action Set、Batch、Sequenceは複数Action間のMaterialな関係を表すConceptであり、固定DB Object / State Machineではない。

Action Set Membership、Batch Identity、Constituent Action Identity、正式Authorization Scopeを区別する。BatchへActionを追加しても既存Authorizationは無条件に拡張されない。変更可能なBatchを正式にカバーするAuthorizationの存在は否定しない。

Batch / Sequenceの正式CoverageはApplicable Governanceに従い、集合があるだけでAtomic Execution / Completion / Cancellationは成立しない。

## 5. Automated Action / Authority Exercise Boundary

Automated Action AttemptはActor / Service / Processが自動的にOperational Actionを試みた事実。

Automated Authority ExerciseはFormal Authorityに関係する行使であり、その適切性はD2〜D4およびApplicable Governanceに従う。

Observed Attempt、Authorization Coverage、Proper Authority Exercise、Execution Success、Observed External Effectを区別する。

技術的に実行・成功したことだけでProper Authorizationを証明しない。一方、正式Coverage内の反復運用へUniversal Per-Action Human Approvalを要求しない。

## 6. Actor / Authority / Delegation Multiplicity

単一Actorの複数Actionと複数Actorの個別Actionを区別する。Actor数 / Service数 / BOT数 / AI Role数から独立したAuthorization数、Approval数、Risk Capacity数を自動生成しない。

Caller Authorization、Callee Applicable Authority、Technical Capability、Information Transfer、Formal Delegationを区別する。

`Caller Authorization != Callee Authority Grant`。ただし正式Delegation / 既存AuthorizationによるService連携を否定しない。

## 7. Individual / Aggregate Authorization Boundary

Individual Authorization Coverageと、Batch、Sequence、Concurrent Action、Aggregate Effectへ正式に適用されるAuthority Requirementsを区別する。

個別Authorizationが成立しても集合的Operation全体の正式適切性は自動的に成立しない。複数Actionの存在だけで新しいAggregate Approvalが必須になるわけでもない。

正式なStanding / Multi-Action AuthorizationやJoint ApplicabilityのScope、Conditions、Temporal Validity、Material Effectを尊重する。D5自身は新たなAggregate Authorization Requirementを発行しない。

## 8. Standing Authorization / Repeated Exercise

反復Authority Exerciseは正式Scope、Purpose、Conditions、Temporal Validity、Restrictionsの範囲に従う。

Standing AuthorizationはUnlimited Repetition、Frequency、Quantity、Aggregate Effect、Target、Time、Unconditional Continuationではない。複数Actorが同じStanding Authorizationを参照してもShared Constraintを無条件に独立化しない。

正当にカバーされた自動反復をUniversal Human Reapprovalの対象にはしない。

## 9. Shared Constraint

複数ActionにMaterialに関係するRisk Capacity、Risk Budget、Exposure Limit、Account Constraint、Operational Resource、Safety Boundary等の共有条件を保持する。

Constraint Observation、Condition Evaluation、Resource Availability、Resource Reservation、Actual Resource Consumption、Aggregate Effectを区別する。

個別Conditionの充足が集合的Constraintの充足を無条件に証明するわけではない。Reservationの存在もProper Authorization、Actual Consumption、Aggregate Safetyを保証しない。

D5は新たなRisk Limit / Capacity AmountやMandatory Reservation / Lock / Transaction / Concurrency Protocolを定義しない。

## 10. Intended / Expected / Observed Aggregate Effect

Intended Aggregate Effect、Expected Aggregate Effect、Observed Aggregate Effect、Material Unknownを区別する。

Aggregate Effectは常に個別Effectの単純加算ではない。Common-Cause Risk、Offsetting Relationship、Execution Timing、Partial Completion、Shared Failure Source等のMaterialな関係を保持する。

`Intended Hedge != Achieved Hedge`。`Planned Offset != Actual Risk Offset`。Net Exposureが小さいことだけで全Risk消滅を推定しない。

Risk Formula、Correlation / Hedge ModelはApplicable Risk Governanceへ委ねる。

## 11. Concurrent Action / Temporal Interaction

Initiation、Authority Exercise、Execution Attempt、External Effect等が重なる可能性を扱う。

複数Actorが同じConstraintを個別評価した場合でも、Concurrent Exercise後のAggregate Effectが正式条件を満たすとは限らない。過去Verificationは、他ActionによるMaterialな状態変化後の充足を無条件に保証しない。

具体的Serialization、Lock、Reservation、Transaction、Distributed Coordinationは後続Runtime Governanceで決定する。実装未固定は正式Constraint無視の許可ではない。

## 12. Action Dependency / Conditional Sequence

他ActionのResult、State、Material Effect、Informationに依存する場合、そのDependencyを保持する。

`Temporal Order != Causal Dependency`。Shared Signal / Shared Decision Origin、Formal Authorization、Actual Effectを区別する。

同じSignalからの複数Actionは、同一Actionや不正Duplicate Orderだと自動判断しない。一方、Shared Originを独立Evidence / Riskとして無条件に扱わない。

前段Actionの成功は後続Authorizationを作らない。前段Failure / Partial / Unknownは後続Conditionsに影響し得るが、D5はUniversal Abort / Continuation / Recovery Ruleを生成しない。

## 13. Partial Completion / Constituent Outcome

一部ActionのみがAccepted、Filled、Completed、Failed、Unknownになる場合、Constituent ActionのMaterialな結果を保持する。

`Partial Completion != Full Completion`、`Partial Failure != Automatic Total Failure`。

Batch Success CriteriaはApplicable Governanceに従い、必ずしも全構成Action成功を要求しない。

Batch StatusがSUCCESS / FAILEDでもConstituent ActionのFormal Authority Exercise、Execution Facts、Observed Effect、Uncertaintyを消去しない。Batch Profit / Successは全ActionのProper Authorizationを証明しない。

D5はAutomatic Rollback / Universal Cancellation / Forced Liquidationを上位原則にしない。

## 14. Retry / Duplicate Exercise

同一または類似Intentionからの複数Request、Authority Exercise、Execution Attempt、Retry、Replay、Resubmissionを区別する。

Same Intention、Same Action Identity、Same Attempt、Same External Effectは異なる。Idempotent Technical Handlingは追加AttemptへのFormal Authorization Coverageを成立させない。

複数Attemptがあっても複数External Effectの発生を自動断定しない。Prior Authorized AttemptはNew Attemptを無条件に認可しない。

実装上のRetry / Idempotency / Deduplication / Order Identification / External ReconciliationはExecution Governanceへ委ねる。

## 15. Authorization Change During Multi-Action Exercise

Standing Authorization、Scope、Conditions、Temporal Validity、RestrictionsはMulti-Action中に変更され得る。

前段ActionがAuthorizedでも後続Actionは無条件にAuthorizedではない。正式なBatch / Sequence Authorizationの効力はApplicable Governanceに従う。

後からのRestrictionが過去のAuthority ExerciseやExecution Factを自動的に書き換えるわけでもない。

Formal Effective Time、Actor Discovery Time、Authority Exercise Time、External Effect TimeのMaterialな違いを保持する。In-Flight管理はD4とRuntime / Execution Governanceに従う。

## 16. Interference / Material Interaction

一方のActionが別ActionのAuthorization Conditions、Shared Constraint、Execution Feasibility、Actual Exposure、Safety Protection、Material Effect等に影響する場合、そのMaterial Interferenceを識別可能にする。

`Interference Identified != Authority to Preempt / Cancel`。発見したことだけでFormal Authority、Priority、Override、Cancellation、Blockingを成立させない。

一方のActionの存在・成功・失敗を別ActionのAuthorization成立・取消の無条件な根拠にしない。

## 17. Compensation / Recovery Action

Partial Completion、Unexpected Aggregate Effect、Execution Failureに対するCompensation / RecoveryもMaterial Effectを持つOperational Actionとなり得る。

`Compensation Purpose != Compensation Authority`。`Recovery Need != Unlimited Recovery Permission`。

正式Authorizationがカバーする補償・Safety Actionの可能性を否定しない一方、Purpose LabelだけでAuthorityを作らない。具体的Compensation / Recovery / Forced ExitはApplicable Governanceへ委ねる。

## 18. Safety / Defensive Exercise

正式に認可されたFast Safety / Defensive / Emergency ActionがMulti-Actionに関係する場合、そのScope、Conditions、Temporal Validity、Material Effectを尊重する。

通常ActionとのMaterial Interferenceを保持するが、D5がPreemption、Override、Cancel、Forced Liquidationを許可・命令するわけではない。

通常ActionへのRestriction / Unknownを、対象外の正式Safety Actionへ無条件に拡張しない。具体的Safety Priority / Execution MethodはApplicable Governanceへ委ねる。

## 19. Unknown / Conflicting Multi-Action State

Authorization、Conditions、Attempts、External Effects、Shared Constraints、Aggregate ExposureがUnknown / Conflictingの場合、その種類とMaterial Impact Scopeを保持する。

Individual KnownはAggregate Knownを意味しない。Aggregate Unknownは全Individual Unknownを意味しない。Material Relationship UnknownをProven Independenceと見なさない。

UnknownをPermission Granted、Formal Denial、Universal Block、Global Forced Liquidationへ自動変換しない一方、未確認の必要Authority / Conditionを無条件な実行許可として利用しない。

## 20. Historical / Exercise Integrity

Individual Action、Actor、Applicable Authorization、Authority Exercise、Execution Attempt、External Effect、Shared Constraint、Aggregate Effect、Material Dependency、Uncertainty、事後評価のMaterialな相違を保持する。

Batch / Strategy / Workflowという集合表現で、Constituent ActionのFormal Exercise / Execution Factを無言で消去しない。

Aggregate ProfitやBatch Successで、過去に存在しないAuthorizationを遡及創作しない。新EvidenceによるHistorical Evaluationの更新と、Historical Factの改変を区別する。

Event Log、Trace ID、Ledger、DB Schema、Monitoring、Audit Implementationは後続へ委ねる。

## 21. Non-Goals / Final Responsibility

D5はFormal Authority Grant、Aggregate Approval Requirement、Universal Per-Action Human Approval、Mandatory Central Controller / Queue / Global Lock / Atomic Transaction / Resource Reservation、Fixed Batch State Machine、Aggregate Risk Formula、Correlation / Hedge Model、Execution Priority、Safety Override、Universal Retry / Idempotency、Automatic Rollback / Compensation、Forced Liquidation、Mandatory Recovery / Runtime Pipelineを固定しない。

**核心:** 複数Operational ActionのIndividual Authority Exercise、Material Multi-Action Relationship、Shared Constraint、Aggregate Effectを区別し、個別Actionの許可・確認・成功・技術的結果から、集合全体の正式許可・安全性・適切性・完了を暗黙的に成立させない。
